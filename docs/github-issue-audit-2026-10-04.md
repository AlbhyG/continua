## Sign-in findings and fixes

- **#60:** Production had no custom SMTP host/user/sender and `rate_limit_email_sent=2`. Sign-in used Supabase Auth directly, bypassing the Resend integration used elsewhere. Supabase's default sender also restricts recipients to project-team addresses. Configured authenticated Resend SMTP (`smtp.resend.com:465`, sender `reply@continua.info`) and a conservative project limit of 30/hour, retaining Supabase's other abuse controls. SMTP authentication succeeds without sending mail. The available October 3 auth logs show seven authentication-option requests and two successful passkey verifications but no `/otp` request. This does not prove Albhy hit a rate limit: the request may have stalled in the browser before reaching Auth. Email now bypasses browser auth storage/PKCE and background credential waits, aborts after 15 seconds, explains rate limits/timeouts, and enables retry. A timed-out email may still arrive if the server accepted it before the connection was aborted. Actual inbox delivery and physical iPhone behavior still need confirmation.
- **#61:** Main already had quiet conditional autofill; its only “Waiting” status was tied to explicit sign-in. Conditional provider failures could nevertheless display visible errors, and cancellation could wait on a provider that ignored abort. Kept all background autofill status/errors silent, made cancellation independently abortable, and changed the explicit option to **Sign in with a passkey**, with cross-device guidance and visible email recovery on failure. No attempt is made to infer device-local credential presence from the account's registered-passkey list.
- **#59:** The header linked to `/login` without context, and `safeNextPath` defaulted to `/my-info`. Header sign-in now preserves path, query, and fragment; context-free sign-in goes home. The validator accepts only relative same-site destinations or HTTPS continua.info/www.continua.info URLs, rejects external URLs/control characters/backslashes and auth loops, and converts valid URLs to relative paths. The callback supports Supabase token-hash verification, while retaining legacy PKCE-code handling. The email template carries the allowlisted callback's `next` inside the token link, so a fresh device needs no original browser verifier. Token-bearing redirects use no-store/no-referrer headers.
- **Multiple passkeys:** Already supported. Sign in on the iPhone using the same email, open My Info → Passkeys, and choose Add a passkey. The laptop passkey remains registered. Chrome's password manager and an iPhone's selected provider need not share credentials. The account list proves registration, not availability on the current device. Added this explanation to settings.

Production email-template release procedure: apply `supabase/templates/sign-in.html` to both `mailer_templates_confirmation_content` and `mailer_templates_magic_link_content` after the callback code is deployed. Allowlist callback URLs with query parameters on both production origins. These are operational settings, not SQL migrations. Keep Supabase management and SMTP credentials out of Git.
